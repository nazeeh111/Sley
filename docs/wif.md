# WIF profile and physical actions

Sley accepts a bounded WIF 1.1 profile. The identity section and CONTENTS must agree with actual sections. Shed direction must explicitly be rising. Active control is either direct LIFTPLAN or TIEUP plus TREADLING, never both. Zero and omitted structure entries mean no connection/action. Threading supports one shaft or no shaft per warp end, retaining every original position.

Pressing a pedal raises its assigned shaft set. Pressing two allowed pedals raises the union of those sets. A plan must equal each requested lift exactly; extra or missing shafts are a failure. Each fixed pedal retains its exact shaft set, including an untied pedal or a pedal never pressed. Only a free pedal may be assigned by the search.

An intersection-closure candidate basis is complete for free effects in this model: enlarging each used free effect to the intersection of the lifts using that pedal remains inside each target and retains its old effect, so the original exact unions and physical actions survive. Unused free pedals may be empty. Fixed effects never change and may be outside that intersection family; the search admits them as union operands. This does not establish optimality, physical suitability or arbitrary WIF semantics.

The search receives at most 128 distinct lifts, active shaft numbers and optional exact fixed assignments. It solves the entire family in one assignment. Repeated picks are expanded from that plan, preserving original indices. No independent batches are combined. Comparison uses cached row bytes and a streaming digest, not a full fabric matrix in HTTP JSON; the browser draws a bounded window from compact arrays.

Input limits: 1 MiB UTF-8 WIF, 32,768 lines, 2,048 characters per line, 4,096 ends/picks, eight shafts, source treadle count up to 64, ten target physical slots. Numeric conversion follows lexical bounds. Import reserves the worst-case rewritten control size under the same byte, line and line-length caps. Excess retained text is refused before search; admitted drafts can export and reopen without stripping metadata. Portable project files allow 7 MiB UTF-8 JSON; requests allow a 16 MiB envelope for that raw JSON string when escaped inside JSON. A palette may have 256 entries with channels in a declared range bounded by 0..65,535. Invalid indices, colors, duplicate keys/sections and unknown control sections are refused, never clamped.

THREADING, TEXT, NOTES, palettes, colors and independent appearance blocks are retained. Unknown private sections cannot be classified safely and are refused. Existing spacing, thickness and symbols are preserved without a fabric-suitability or comprehensive appearance-validation claim. Header source-program/version fields identify Sley. Output replaces the active controls with exactly one physical-ID tie-up/treadling path and updates CONTENTS. Empty positions remain declared and untied. Export reparses its own complete WIF and checks original threading/lifts and preserved independent blocks before a ZIP is built.

The annotated [Bower WIF reference](https://asunder.co/app/bower/articles/wif-file-specification) and actual [dtx_to_wif](https://github.com/r-owen/dtx_to_wif) readback informed this profile. Bower implementation notes are not a normative specification. The original normative reference was unavailable during this implementation, so Sley does not claim full WIF 1.1 compliance or compatibility with every reader.
